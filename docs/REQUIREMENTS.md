# Requirements

Version 0.1 scope. Supersedes the original "Application Proposal (Proposed PoC)"; the changes and their reasons are in `PROPOSAL-REVIEW.md`. Priorities: **MUST** (v0.1), **SHOULD** (v0.1 if time allows, else v0.2). Milestones M1..M4 are defined in `ARCHITECTURE.md`.

## Scope

An engineer connects to a SunSpec device, discovers all model instances, inspects fully decoded points, reads once or polls, and exports or records measurements. The same engine runs in two places: inside the desktop application (Local), or in the headless daemon on a gateway, which a browser reaches through an SSH port forward (Remote). The desktop application has no remote mode.

**Non-goals for v0.1**: any Modbus write, device control or settings changes, charts and dashboards, multi-user access, cloud services, databases (SQLite/Parquet), a built-in SSH client, a remote mode in the desktop GUI, TLS on the daemon's listener (use the SSH forward), protocol traces, simulation (that is `sunspecctl serve`).

## Programs

| Program | What | Runs on |
|---|---|---|
| `sunspec-explorer` | Wails v3 desktop GUI. Local mode only: in-process engine, no daemon client | macOS (arm64, amd64), Windows amd64 (MUST) and arm64 (best effort), Linux desktop amd64 and arm64 (no armv7: Wails v3 does not support it) |
| `sunspec-explorerd` | Headless daemon: HTTP API + SSE, owns sessions, polling and recordings, serves the embedded web UI to a browser (the only remote client). No GUI toolkit, no cgo | Linux arm64, armv7 and amd64 (all MUST; gateways run Debian 11, 12 and 13), macOS and Windows for development |

## Requirements

| ID | Pri | M | Requirement |
|---|---|---|---|
| R1 | MUST | M1 | **Connection by URL.** Target = URL (`tcp://host:port`, `rtuovertcp://host:port`), Modbus unit ID, timeout. Advanced: register type (holding/input), base-address list (default probes 0, 40000, 50000 and neighbours), max models. Serial (`rtu://<device>`, with baud, data bits, parity, stop bits; default 9600 8N1) and Modbus/TCP Security (`tcp+tls://host:port`) are implemented. A TLS target uses the identity the engine was started with (`--tls-cert`, `--tls-key`, `--tls-ca`): a client never sends key material or file paths. On the daemon, serial paths refer to the daemon's machine. |
| R2 | MUST | M1 | **Discovery.** Run detect then discover. List every model instance in chain order with ID, name, start address, length, `SchemaKnown`, `DecodingSupported`. Show discovery warnings. On failure show every probe attempt and its error (wrong unit ID is the usual cause). A "Re-discover" action. |
| R3 | MUST | M1 | **Model browser.** Sidebar = chain order (the same model ID may occur more than once). Each model expands into its group tree (repeating groups as instances, e.g. MPPT module 1, 2). Point table fields: model, point name, label, description, units, type, access (R/RW), mandatory, static, implemented, raw value, scaled value, scale-factor name and raw value, enum/bitfield symbols, absolute register address (zero-based, as go-sunspec reports; optionally also the SunSpec-documentation 1-based form, clearly labeled), register offset. Search/filter over name, label, description. "Show raw details" toggle. Models without a schema show raw registers, labeled as undecoded. |
| R4 | MUST | M1 | **Single read.** All models or a selection. Each model reports its own status (`ok`, `error`, `changed`), error text, duration and warnings. A partial failure never hides the models that succeeded. |
| R5 | MUST | M1 | **Polling.** Runs in the Go engine, never with frontend timers. Interval: whole seconds, default 5 s, minimum 1 s. Scope: selected models; default = all models except static-only ones (e.g. Common), which are read once and on demand. Start-to-start timing with skip-if-busy (no catch-up bursts, overruns counted). Never overlaps a read in the same session; a user "single read" during polling is queued on the same connection. Last good values stay visible and are marked stale after 2 missed intervals. Failures are recorded, never silently replaced by old values. Records actual sample time and read duration. Reconnects with backoff; `ErrModelChanged` triggers re-discovery and an event. |
| R6 | MUST | M1 | **Export snapshot** as JSON (schema in `ARCHITECTURE.md`): target, base address, timestamps, app and library versions, model instances, decoded points with units, raw values, metadata level `full`, warnings, raw registers for unknown models. Warn that exports can contain serial numbers and network addresses. Also implemented: CSV in long format (one row per point; of a single read and of a recording) and a device-file export that `sunspecctl serve` turns back into the same device. The snapshot's JSON Schema is published in `docs/schema/snapshot-1.schema.json`. |
| R7 | MUST | M3 (implemented) | **Recording.** JSON Lines time series produced by the engine that owns the session (the daemon in remote operation): header line, one line per sample, event lines (gaps, chain changes), footer on clean stop. UI: start/stop, elapsed time, sample count, failure count, file size and path/name. Size-based rotation. On the daemon it survives a closed browser tab and tunnel loss. After a daemon restart, an interrupted recording is listed as `interrupted` and downloadable. Downloadable while in progress and when complete (HTTP Range supported). **Storage:** recordings live in the engine's data directory, which defaults to a temporary folder (`<tmp>/sunspec-explorer-<uid>`, created 0700; the daemon refuses a directory that is a symlink, has another owner or has wider permissions). That storage is ephemeral: it is lost when the OS clears the temp dir (a reboot; Debian 13 mounts `/tmp` as tmpfs, i.e. RAM-backed). The UI therefore shows where a recording lives, warns that it is temporary, and offers to save a copy when a recording stops (native Save dialog in the GUI, browser download in the web UI). `--data-dir` selects persistent storage. Recovery of interrupted recordings works across daemon restarts, not across a clear of the temp dir. |
| R8 | MUST | M1 | **Local mode** is the only mode of `sunspec-explorer`: in-process engine. The GUI has no remote mode, no daemon client and stores no token. |
| R9 | MUST | M2 | **Daemon** `sunspec-explorerd --listen 127.0.0.1:8765`: no display, no GUI libraries, static binary that runs unchanged on Debian 11 (Bullseye), 12 (Bookworm) and 13 (Trixie) on amd64, arm64 and armv7. Flags for data directory, token file, allow-lists, limits. Graceful shutdown on SIGINT/SIGTERM. A systemd unit example ships in `packaging/`. |
| R10 | MUST | M2, M3 | **Remote operation = daemon + SSH port forward + browser.** The desktop GUI has no remote mode. On the gateway: start `sunspec-explorerd`. On the workstation: `ssh -N -L <port>:127.0.0.1:<port> user@gateway`, then open `http://127.0.0.1:<port>/#token=...` in a browser (R21). No desktop install and no Wails on that path; a built-in SSH tunnel is out of scope. M3 adds what makes this convenient: **(a)** `sunspec-explorerd url` prints the full URL with the `#token=` fragment, ready to paste, using the address and port the running daemon actually bound, and the suggested `ssh -N -L` command when the hostname is known; **(b)** token lifecycle (R13): generated on first start, kept in a 0600 file, rotatable. |
| R11 | MUST | M1 | **Read-only.** Only FC03 and FC04 are ever emitted. Enforced by allow-list at the lowest layer available (see `ARCHITECTURE.md` section 9), lint bans, and a wire-capture test. The go-sunspec `Server` is test-only. |
| R12 | MUST | M4 | **Portability and build matrix** as in "Programs". Linux GUI builds target GTK4 + WebKitGTK 6.0 (Wails v3 default); a `-tags gtk3` variant only if a required distro lacks WebKitGTK 6.0 and only while Wails supports it (removed in v3.1). Debian as a GUI host: Trixie (13) is expected to ship WebKitGTK 6.0 (verify with `wails3 doctor`); Bookworm (12) needs the `-tags gtk3` variant; Bullseye (11) is not covered by the Wails documentation and is unlikely to work. Gateways are headless, so none of this affects the daemon. Windows arm64 GUI is best effort: build it in CI only if it needs no extra work, no dedicated test device, and never block a release on it; Windows 11 on ARM can run the amd64 build under emulation. There is no armv7 GUI. |
| R13 | MUST | M2 | **Daemon authentication.** A random bearer token is required on every request, even on loopback. It is generated on the first start, stored in a 0600 file (default `<data-dir>/token`; `--token-file` overrides) and reused by later starts until it is rotated (`sunspec-explorerd token rotate`, M3) or the file is gone. The token is never logged; it is shown only by the `url` command and, when the daemon writes to a terminal, in the one startup line of R21. Default bind is `127.0.0.1` only. Binding any other address needs the explicit flag `--allow-remote-bind`, prints a warning (the traffic, token included, is not encrypted) and still requires the token and the Host check. The Host header must name a host the daemon answers to: the loopback names, plus the bind address and `--allow-host` names for a remote bind; the port is not compared, because an SSH forward may use another local port. SSE via fetch streaming (not `EventSource`, which cannot send headers). |
| R14 | MUST | M2 | **Target allow-list.** The daemon only connects to CIDRs and serial devices it is configured to allow (default: private ranges; no serial device until the operator names them with `--allow-serial <pattern>`). The desktop application, which runs as its user, opens any serial device that user may. Prevents use as a network scanner. |
| R15 | MUST | M2 | **Limits.** Max sessions (default 4), min poll interval (1 s), request pacing delay between two model reads (`--request-delay`, default 0), max recording size and duration (defaults for a RAM-backed temp dir: 64 MiB per recording, 256 MiB in total, 7 days; configurable), recording directory free-space floor (64 MiB by default, `--min-free-mb`: below it no recording starts and a running one is stopped with reason `disk_space`), fixed recording directory (clients send names, never paths). |
| R16 | MUST | M2 | **Version handshake.** `/health` returns app version and API version. The web UI is served by the daemon it talks to, so the versions normally match; a page that is older than the daemon (a tab left open across an upgrade) notices it when the connection comes back: an incompatible API major version blocks the page with a Reload button, any other version change shows a banner that offers a reload. |
| R17 | SHOULD | M3 (implemented) | **Time.** All timestamps UTC RFC 3339 with nanoseconds, display in local time with UTC on hover. Warn when the daemon clock differs from the browser's host by more than 5 s. |
| R18 | MUST | M1 | **Branding and accessibility** per `BRANDING.md`: dark default plus light theme, tokens only, WCAG AA text contrast, full keyboard navigation of the sidebar and table, no color-only status. |
| R19 | MUST | M2 | **Logging.** Structured logs to stderr (journald-friendly). No token, no credentials, serial numbers only at debug level. |
| R20 | SHOULD | M4 (first cut in v0.0.1) | **Distribution, unsigned for now.** No macOS or Windows signing identity exists. Ship SHA-256 checksums, CI build provenance attestations, and install notes for Gatekeeper (arm64 macOS binaries are at least ad-hoc signed; users approve the app in System Settings > Privacy & Security or remove the quarantine attribute) and SmartScreen (More info > Run anyway), as `sunspecctl` already documents. Linux deb/rpm/AppImage via Wails packaging (optionally PGP-signed with a project key), daemon tarballs per architecture (like `sunspecctl`), and a multi-architecture container image of the daemon (amd64, arm64, armv7; `packaging/Dockerfile`: static binary on a distroless base, non-root, data in the `/data` volume), which is also the way to try the daemon on macOS and Windows. **v0.0.1** ships the daemon tarballs, the image (`ghcr.io/otfabric/sunspec-explorerd`), a macOS application bundle (ad-hoc signed, zipped), a Windows executable and a plain Linux binary, with the checksum file and provenance attestations; installers and packages (dmg, msi, deb, rpm, AppImage) follow in M4. All builds run on runners of the target architecture, without emulation. Revisit signing before wide distribution. |
| R21 | MUST | M2 | **Browser mode.** The daemon embeds the web build of the frontend and serves it at `/` next to `/api/v1`, so any current browser (latest two major versions of Chrome, Edge, Firefox, Safari) gets the full UI through the SSH tunnel, or locally against a daemon on the workstation (useful where the Wails GUI cannot run, e.g. Debian 11/12 desktops). The token is passed in the URL fragment (`http://127.0.0.1:8765/#token=...`, printed by `sunspec-explorerd url`; the daemon also prints it at startup, but only when it writes to a terminal, so that the token does not end up in a journal or a container log), read by the page, kept in memory, stripped from the address bar and sent as an `Authorization` header. No cookies, no CORS headers (same origin), strict CSP (`default-src 'self'`, no inline script). Exports and recordings are saved through browser downloads. `--no-ui` serves the API only. Same features as the desktop application. This is the only remote client (R10). |

## Acceptance tests

Test infrastructure: go-sunspec `testutil` fixture server and an in-process `sunspec.Server` (test files only), plus go-sunspec's chaos proxy approach for fault injection. Do not depend on the `sunspecctl` binary in CI.

| ID | Test |
|---|---|
| A1 | Discover and fully decode a simulated device in Local mode, including models 1, 103, 160 (repeating MPPT modules) and 705 (nested curve groups). |
| A2 | Point table shows label, description, units, scale factor, enum symbols and bitfield flags correctly; unimplemented points are labeled, not shown as 65535. |
| A3 | Two instances of the same model ID are both listed in chain order and addressable independently. |
| A4 | Unknown vendor model (e.g. 64900) is listed and read as raw registers with a clear label and a warning; it is included in the export. |
| A5 | Single read and sustained polling at 1 s and 5 s; no overlapping cycles; overruns are counted; a single read during polling is serialized. |
| A6 | Per-model failure (inject an exception on one model's address range): other models stay fresh, the failed one is marked and stale, the failure is in the recording. |
| A7 | `ErrModelChanged`: change the simulated chain mid-run; the engine re-discovers, emits an event, and the sample stream shows the gap. |
| A8 | Export a complete snapshot; the JSON validates against the published JSON Schema (`docs/schema/snapshot-1.schema.json`; checked in `internal/engine/schema_test.go` for full, compact, raw and failed-model snapshots) and contains versions, base address, warnings and raw registers for unknown models. |
| A9 | In the browser, start a recording on the daemon; close the tab and kill the tunnel; re-establish the tunnel and open the URL again: sample count continued, file downloadable. Kill and restart the daemon: recording shows `interrupted` and downloads (same data directory; loss after the OS clears the temp dir is expected and documented). |
| A10 | One `Service` contract suite passes against the engine directly and against the daemon's HTTP API wrapping an engine (the test drives the API with plain `net/http`; there is no Go client package). The same UI smoke suite passes in the Wails build (Local) and in the web build against a daemon. |
| A11 | Wire capture: across all user-reachable workflows only FC03/FC04 appear on the wire. Lint fails the build if a `Write*` call or the go-sunspec `Server` appears in non-test code. |
| A12 | Daemon runs with no `DISPLAY` on linux/arm64, armv7 and amd64, each on Debian 11, 12 and 13 (containers, plus at least one real gateway per architecture): `file` reports a statically linked binary, a container without GTK runs it, `go list -deps` contains no Wails packages. |
| A13 | Daemon rejects requests without the token or with a wrong one (the token counts in the `Authorization` header only), with a wrong Host header, and connect requests outside the allow-list; recording names with path separators are rejected. |
| A14 | 24-hour soak: polling plus recording at 1 s; memory flat; recording file valid after a forced kill (truncated last line tolerated). |
| A15 | Browser mode: with the daemon behind an SSH tunnel, a current browser loads the UI, authenticates with the fragment token (fragment stripped from the address bar; token never in a query string, cookie or log) and passes the same UI smoke suite as the desktop application in both themes; responses carry the CSP and no CORS headers; `--no-ui` returns 404 for `/`; exports and recordings download. |
| A17 | `sunspec-explorerd url` prints `http://<bound address>:<bound port>/#token=<token>` for the running daemon (also when `--listen` used port 0) and an `ssh -N -L` suggestion with the gateway's hostname. The token file is created 0600 on first start and reused on restart; after `token rotate` the old token is rejected and the new one works without a restart. The token appears in nothing the daemon writes unless that goes to a terminal (R21). |
| A18 | Container image: it builds for amd64, arm64 and armv7; the container runs as a non-root user, answers 401 without the token and 200 with the one `docker exec <name> sunspec-explorerd url` prints, serves the web UI, keeps its token in the `/data` volume across restarts, and stops cleanly on `docker stop`. |
| A16 | Data directory: the daemon creates `<tmp>/sunspec-explorer-<uid>` with 0700, refuses a symlink, a foreign owner or wider permissions, and enforces the temp-dir size defaults; the shipped systemd unit does not set `PrivateTmp=` (it would delete recordings when the service stops). |

## Open decisions

None blocking. Recording format (JSON Lines), packaging (two artifacts), temp-dir default, browser mode and remote = daemon + browser (no GUI remote mode) are decided. Revisit signing and a persistent default data directory before a public release.
